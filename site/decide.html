The full request → decision → trace loop

A request carries state, questions, and policy. The engine returns a decision per question with a multi-dimensional confidence report, execution metrics, and a deterministic trace. Refusals are rendered as the outcomes they are — the gate working, not an error.

Refusal codes — every way this engine says no
ir.empty_candidates
Request carried an empty candidates set — there is nothing to choose between.
schema.*
The request did not match the canonical IR schema — the family covers invalid_json, missing_field, invalid_type, invalid_value, limit_exceeded.
graph.cycle
The declarative DAG contains a cycle; run it after breaking the loop.
engine.missing_backend
Graph needs a rung 5–7 backend (embedding / model / verifier) this tab does not ship.
below the gate (no code)
Not a refusal — when calibrated confidence lands under the gate the answer ships as an HTTP 200 abstain, not an error.

Booting the WASM engine…

Graph mode — declarative DAG

A graph chains steps — normalize, decide, gate, output — in one request. Validation checks shape and acyclicity locally; running feeds it through the same WASM engine.

What this is — and what it is not

  • Real: the WASM module is built from this repo's opencodifier-wasm crate — the identical IR, rule engine, narrowing, lexical scorer, cache, and calibration code the CLI and HTTP server run.
  • Real: the zero-ML stack only. Rungs 5–7 (embedding, decision model, verifier) need backends this tab deliberately does not ship; a graph that needs one returns engine.missing_backend instead of pretending.
  • Not here: network calls, telemetry, or model downloads. The Network chip counts cross-origin requests from the Performance API — if it ever reads anything but zero, the page is broken, and the chip will say so.

Prefer a terminal? The same decisions from cargo run --bin opencodifier-cli -- decide, or serve the HTTP API and hit the documented endpoints.
